# Quality Report — grade 1, all five books

What the pipeline produced for every grade-1 book that exists, and what each
number is worth. Every figure here was computed from the built packages and the
L0 validation reports, never from a run summary's own account of itself, and
nothing was rounded in the pipeline's favour.

The science book is the **frozen baseline**: its concept and objective
artifacts are not regenerated by later work, and the section on it below is
carried forward unchanged from when it was measured. Everything else in this
report is new.

## How to read the empty columns

Four columns are zero for every book, and they are the most important columns
in the report.

`skills`, `relations`, `activities` and `questions` are empty because **nothing
in this pipeline may fill them**. Which objectives add up to one transferable
skill, which concept must come before which, what a child should do to
practise, and what would show they can — a first-grade textbook teaches all of
it and states none of it. A model asked to supply the missing half supplies it
fluently, and nothing in the resulting package would distinguish a real
ordering from a plausible one.

So they enter through `content_assistant/authoring/` or they do not enter. No
such content has been authored yet. **The zeros are the record of work not
done, not a gap for a model to fill.**

`g1-riazi` is empty for a different reason, and it is also correct. That book
prints no contents list of any kind — cover, colophon, two forewords, teacher
notes, then page 1. Nothing names a unit and a page, so no lesson boundary
exists to be read. `STRUCT011` reports it rather than letting an empty package
pass as a processed one.

The assembled package holds **99** evidence records rather than 82: it is the

Every quotation matched exactly — none by the normalized or fuzzy path — so no

worth keeping: it is the structural rule that stops an objective from becoming
a new concept, and it held on real data without a single exception.

### Vocabulary (PEDA009)

Six flags, each read back against the lesson it came from:

| class | count | verdict |
|---|---|---|
| A — ligature artifact: the book **has** the word, mangled | 3 | false positive |
| B — morphological: the root **is** in the book | 2 | false positive |
| C — genuinely absent from the lesson | 1 | correct flag |

Class A is the reversed lam-alef defect in the PDF's text layer: the book
spells `سلامت` as `سالمت` (twice, lesson 3) and `خلاقیت` as `خاّلقیت`
(lesson 8). The model wrote the words correctly and was flagged for it.

Class B is prefix matching meeting Persian morphology: `چیزی` against the
book's `چیزهای`, and `کرده` against `کردی` (lesson 1). Same three-letter root,
different inflection.

Class C is a single word, `قرار` in lesson 1, which shares not even two leading
letters with anything in that lesson. The flag is correct by the rule. But
`قرار گرفتن` is a light-verb construction and `قرار` carries almost no meaning
on its own, so what leaked is grammar, not knowledge.

**No general knowledge, and no technical term above the book's level, entered
any of the 79 objectives.**

### Observability

78 of 79 observable. The one exception, lesson 13:

```
statement : توضیح دهد که آهنرباها گاهی یکدیگر را جذب می‌کنند.
verb      : 'توضیh دهد'      ← Persian ح replaced by a Latin h
```

A character-level corruption in the model's output, not a pipeline fault: the
statement itself is sound and its quotation matched exactly. The closed verb
lexicon caught it precisely because matching is a lookup rather than a
judgement — a free-form "does this look like a verb?" check would have accepted
a string one character away from a valid one. `PEDA001` fired, and the
objective is in the review queue rather than in the output as if it were fine.

## What the other four books added

### The silence that looked like a finding

The largest thing the other books surfaced is not in any of their concepts. It
is in the lessons that produced none.

Seventeen lessons — 12 in فارسی, 5 in نگارش — were shown their text and came
back with an empty list. None was a *failed* call: the pipeline already refuses
to record those (`ModelCallFailed`). None was a proposal rejected for want of
grounding either — `ungrounded` is zero in every one of the seventeen
artifacts. The model was asked, answered, and said nothing.

The artifact that results is byte-for-byte the artifact of a lesson that
genuinely holds no teachable claim. It validated clean, assembled into a clean
package, and nothing anywhere reported it. That is how the first farsi package
came to state that 12 of its 33 lessons teach nothing, with zero validation
errors.

It splits by model, though not cleanly enough to blame one:

| model | lessons given | came back empty |
|---|---|---|
| `gemini-3.5-flash-lite` | 23 | **12** |
| `gemini-3.6-flash` | 22 | **5** |
| `gemini-3.5-flash` | 30 | 0 |
| science, adapter recorded only | 14 | 0 |

The lighter model is much worse at it — half the lessons it was given — but the
flash model does it too, while `gemini-3.5-flash` did it on none of the thirty
it answered. And the two books with no empty lesson at all, `g1-olom` and
`g1-quran`, are also the two shortest and most expository. So it is neither
purely a model defect nor purely a property of the books, and the honest
summary is that it is not yet explained.

**What was done about it.** The 12 فارسی lessons were put back to the stronger
models with `--force`, across eight (key × model) quota buckets, deliberately
excluding the lite model. Every bucket was already spent for the day, so not
one lesson was re-answered; the artifacts on disk are unchanged, because a
failed call writes nothing. The 5 نگارش lessons were not retried for the same
reason — there was no quota left to retry them with. Both sets remain open
work, and `STRUCT013` is what will keep them visible.

**What was not done about it.** No concept was written for those lessons by any
other means. A lesson that a model declined to describe is not a lesson the
pipeline may describe on its behalf.

So the gap is reported instead. `STRUCT013` fires on a lesson with real text
and no concept, as a warning, above a configurable character floor
(`min_chars_for_expected_concept`, 200 — roughly a paragraph; below it a
one-page free-choice lesson may truly hold no claim). Sixteen findings — the seventeenth
empty lesson, a one-page درس آزاد of 76 characters, sits below the floor and is
left alone. The frozen science baseline is untouched: `g1-olom` and `g1-quran`
produce zero. The packages still say those lessons hold nothing. They no longer say it
quietly.

### A third class of wording flag

The science book produced two classes of false positive — a mangled ligature
and Persian morphology. The workbooks produced a third, and it is not a defect
in the check.

`نگارش` is a workbook. Each lesson prints roughly a hundred characters, almost
all of it instructions: `کامل کن`, `رنگ بزن`, `بنویس`. A concept that says what
such a lesson *teaches* has to reach for words like `فعالیت`, `تمرین`, `کلمه`
and `زبان فارسی` — and those words are in the book (29 occurrences of `کلمه`
alone) but not on the two pages of the lesson being described.

`PEDA009` asks whether a claim is worded the way **its lesson** words things,
so the flags are correct by the rule. Whether the rule should ask about the
lesson or about the book is a real design question, and it is deliberately left
open here: changing it would loosen the check for every book to fix a class
that only appears in the two workbooks, and the science measurements above were
taken under the current rule.

### Text-layer damage varies, and it shows

`نگارش` recovers 95.0% of its raw characters against science's 99.9%, and the
residue is visible in the quotations: `تصویر` arrives as `تصور`, `بنویس` as
`بنوس`, `هر` as `زر`. The pipeline quotes what the text layer contains, which
is the correct behaviour — a verifier that "fixed" quotations would no longer
be verifying anything — but it means some grounded quotations are verbatim
copies of a damaged source rather than of the printed page.

This is the same defect class already documented for the lam-alef ligature,
one degree worse. It is a reason to look at these pages, not a reason to
distrust the grounding: every one of those quotations was found, exactly, in
the block it was attributed to.

### Model provenance is now per entity

The frozen science run recorded its model as
`marker.services.gemini.GoogleGeminiService` — the adapter, not the model. A
service class is stable while the model behind it is not, so that artifact
cannot say which model actually answered.

New runs record `<import path>@<model>`. It matters immediately: the free-tier
daily quota is per project **and per model**, so the later books were run
across a rotating pool of keys and models. The "models that answered" list
above is the honest account of that mix, entity by entity, rather than a claim
that one model produced a book.

## Known limits, carried forward deliberately

- **Reversed lam-alef in the source PDFs.** `کلاس` arrives as `کالس` in ten of
  fourteen science lessons. The broken spelling collides with real words
  (`سال`, `حال`), so `text/persian.py` reports these for human review instead
  of guessing at a repair. Cost: three of science's six wording flags.
- **Prefix matching cannot see a Persian prefix.** `متفاوت` in the book does
  not vouch for `تفاوت` in a claim.
- **`min_word_length = 4` hides three-letter words.** `دما` and `ذوب` cannot
  be detected in any lesson. Harmless for grade 1, where neither appears;
  it is configurable per book and should be revisited before a higher grade.
- **The wording check is scoped to the lesson, not the book.** See the third
  flag class above. Left as is, on purpose.
- **Nothing auto-accepts, and the threshold is not why.** Measured in full
  above for science; the same inheritance holds on every other book.
- **Sixteen lessons hold no concept because a model said nothing.** Reported by
  `STRUCT013`, not filled in. Retrying them needs quota that was already spent;
  it is the first thing to run on a fresh day, and the packages will change
  when it succeeds.

## Reproducing these numbers

The artifacts are not in the repository — they are run outputs, and the books
are not ours to redistribute. Each lesson directory holds the prompt that was
sent, the model's raw reply, the verified result, a validation report and a
review file. Regenerating them needs the source PDFs, the L0 extractions, and a
model.

```bash
python -m content_assistant.structuring.semantic.run_book \
    --l0 work/<book>/l0_extraction.json \
    --concepts l1/<book> --objectives l2/<book> \
    --llm marker.services.gemini.GoogleGeminiService

python -m content_assistant.package.build \
    --l0 work/<book>/l0_extraction.json \
    --concepts l1/<book> --objectives l2/<book> --out content/
```

A package build is deterministic: rebuilding one from unchanged artifacts
produces a byte-identical file apart from its `built_at` stamp. That was
checked for the science baseline, and it is what makes a diff between two runs
mean something.
